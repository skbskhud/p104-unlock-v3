# P104-100：PCIe Gen2 x4 解锁 + 宽度声明 x16（Windows，完整开源）

**中文** | [English](README.md)

> NVIDIA **P104-100**（GP104 矿卡，`10DE:1B87`）专用 Windows 工具：
> 出厂 **Gen1 x4（≈0.78 GB/s）** → 解锁为 **Gen2 x4（实测 ≈1.55/1.69 GB/s）**，
> 同时写入 **宽度声明 x16**（`LnkCap maxwidth = 16`），由后台任务常驻保持。
> 实测掉速恢复：**Gen2 0.23–0.25 秒、x16 声明 0.73–0.84 秒**。

## 当前版本：v3.3（工具 v1.2）

## 实测结果（2026-10-30/31，本机单卡，CPU 直连 x16 槽）

| 项目 | 结果 |
|---|---|
| 解锁路径 | **live 写组，无需整卡复位**（0 次复位；出厂态重启后约 5 秒完成） |
| PCIe 链路 | **Gen2 x4**（`LNKSTA = 0x00001042`） |
| `LnkCap` 声明 | maxspeed = Gen2、**maxwidth = x16**（`0x00454D02`） |
| CUDA 带宽（页锁定） | **H2D 1.55 / D2H 1.67 GB/s**（Gen1 x4 参考 0.78 / 0.85） |
| 掉速恢复（v1.2） | Gen2 **0.23 / 0.23 / 0.25 s**；x16 声明 **0.73 / 0.82 / 0.84 s** |
| 每次 Gen1 停留 | 中位 **0 秒**、平均 0.9 秒 |
| 常驻保持 | 20 ms 看门狗，只在偏离时补写 |
| 开机自启 | 计划任务：开机 +90 s / 登录 +120 s / 每 5 分钟自愈（v1.1 已实测冷启动通过） |
| 失败兜底 | live 连续失败才做整卡复位，单次运行最多 1 次（同一开机周期最多 2 次、间隔 ≥10 分钟） |

寄存器指纹（同卡同槽，可用 `状态.cmd` 核对）：

```
               Gen1 出厂        Gen2 解锁后
LNKSTA         0x00001041       0x00001042      ← 当前链路速率
LNKCAP2        0x00000002       0x00000006      ← 声明支持的速率
LNKCAP         0x00463C41       0x00454D02      ← maxspd=Gen2, maxwidth=16
LINK_CONFIG_0  0x20585800       0x20545800      ← 0x8C040（SPEED=1）
```

> 说明：GPU-Z / nvidia-smi 的"支持速率/宽度"是**驱动上报值**，在这张卡上不可靠（常见显示 1.1 x4），
> 以 `状态.cmd` 的 `LNKSTA` / `LNKCAP` 原始值为准。

## 物理层实测（2026-10-31）

在本机 P104-100（VBIOS `86.04.7a.00.19`，subsys `1237:10DE`）补焊 AC 耦合电容（0402 100nF X7R）后，
物理宽度仍无法训练到 x16。已完成的验证：

| 路径 | 结果 |
|---|---|
| 运行时写 `0x8C040` arm + retrain | 声明 16 ✅、物理 x4 ❌ |
| 停 NVIDIA 驱动后写 + retrain | 仍 x4 |
| 完整复位（restart/disable-enable/remove-scan） | 仍 x4（复位确实生效） |
| XVE 位穷举（117 位、1224 万次采样） | **0 位改变宽度**；`0x8C080` 恒 `0x0404` |
| 停驱动 + 写 `0x88140`（LINK_WIDTH16\|COMMIT）/`0x88084`/`0x8C080`/`0x88460` | 特权门 `0xBADF5040`，写入被硬件丢弃 |
| VBIOS 只读分析 | DevInit 从不写宽度字段，启动 x4 不是 VBIOS 设置 |

**结论（截至 2026-10-31）**：软件/固件侧没有找到可用的宽度入口；x4 来自 PHY/strap/板级。就目前的破解手段而言，x16 暂时无法实现；需要时间寻找其他 P104 样本/批次继续验证。**部分批次可能不同**（网上有成功案例），
需对比 PCB 走线与真实 `LNKSTA` 宽度/带宽证据。完整实验记录与原始数据见
[`docs/09-物理层实测记录-2026-10-31.md`](docs/09-物理层实测记录-2026-10-31.md) 与 [`docs/evidence/`](docs/evidence/)。

**卡点（欢迎指教）**：我们卡在两个地方——① 上电 strap 声明为 4（第一次训练必然 x4）；② 运行时改声明后链路不重新走 Detect（Retrain 只进 Recovery，Link Disable 会掉卡）。如果你知道 strap 存在哪/怎么改，或能让链路重新检测 lane 且不掉卡，欢迎开 Issue/Discussion。详见 [`docs/09`](docs/09-物理层实测记录-2026-10-31.md) 第 7 节。
**补充**：本包已内置「声明 arm + 宽度重训」逻辑。如果某块 P104-100 的**板级（strap/走线/电容）原生支持 16 lane**，本包**可能**通过重训直接解锁物理 x16；但本机这块板尚未实测成功（补电容后仍 x4），需要更多样本验证。

## 下载与使用
在 **Releases** 下载 `P104-2.0x16-v1.2.zip`（或本仓库同名目录），**完整解压**后：

1. 右键 **`自动解锁.cmd`** → **以管理员身份运行**；
2. 看到 `SUCCESS` 后**可以直接关窗口**——保持进程在后台 SYSTEM 任务里，重启后自动重新解锁；
3. 验证：运行 `状态.cmd`，应显示：
   ```
   RESULT: 已解锁：Gen2 x4（5.0 GT/s）   [声明宽度 x16]
   判定依据：数据时间 …（新鲜 ≤5s） | 保持进程 运行中 PID … | 计划任务 已注册
   ```
4. 带宽测试：`带宽测试.cmd`（约 1.55/1.69 GB/s）。

**命令参考**

| 文件 | 作用 |
|---|---|
| `自动解锁.cmd` | 安装 + 注册计划任务 + 立即解锁 + 等待结果（管理员；**推荐**，窗口可关） |
| `状态.cmd` | 只读查看链路/声明/保持状态（含判定依据；非管理员可用） |
| `带宽测试.cmd` | CUDA 带宽实测（会让链路临时降速，结束自动等恢复） |
| `停止按住.cmd` | 停止保持（链路回 Gen1，正常） |
| `卸载.cmd` | 卸载任务/驱动（默认保留策略键） |
| `手动解锁-仅实验用-窗口不能关.cmd` | 仅排障用：前台常驻，**窗口不能关**，日常请用自动版 |

**窗口能不能关？**

| 方式 | 窗口能关吗 | 说明 |
|---|---|---|
| `自动解锁.cmd`（推荐） | **能** | 保持进程在后台任务里；关机/重启后自动恢复 |
| `手动解锁-仅实验用…` | **不能** | 窗口就是保持进程，关窗口 = 停止（回 Gen1，正常） |
| 重复运行 | 安全 | 已解锁时跳过写入/复位，只重启一次保持进程（短暂回落，几秒恢复） |

**等待时间**

| 场景 | 需要多久 |
|---|---|
| 开机自启 | 任务在 **开机 +90 秒**触发；触发后 **3–10 秒**完成解锁（开机后等 2–3 分钟再查最稳） |
| 状态显示"正在自动恢复" | 等 **20 秒**再查 |
| `带宽测试.cmd` | 临时降速 10–20 秒；脚本最多重试 4 次、结束最多等 30 秒 |
| 计划任务重试 | 开机 +90s / 登录 +120s / 每 5 分钟一次（失败不会反复复位：单次运行最多 1 次兜底复位） |

## 掉速与恢复（必读）

NVIDIA 驱动在初始化/唤醒 GPU、建立 CUDA 上下文时会重写这些易失寄存器 → 链路瞬时回 Gen1、宽度声明被冲掉。
v1.2 的 20 ms 看门狗会在 **0.23 秒内**把速度拉回、**0.8 秒内**把声明拉回；没有程序碰 GPU 时链路稳定（实测 6 分 40 秒零掉速）。

- GPU-Z / MSI Afterburner 轮询、浏览器硬件加速、游戏启动器、聊天软件都可能触发一次（2–5 秒内自愈）；
- 游戏负载期间主体保持 Gen2；如果在意观感，玩游戏时关掉 GPU-Z/Afterburner；
- 物理 x16 需要硬件支持（PHY/板级），本卡目前尚未实现；工具会在每次掉速恢复后重训宽度并如实报告结果。

## 工作原理（v1.2）

1. 通过 BYOVD 驱动（WinRing0 / ThrottleStop）映射 GPU BAR0；
2. 写入 **live 声明写组**（实测可实时把 PCIe 声明从 Gen1 翻到 Gen2）：
   `0x8872C = 6` → `0x2241C |= 0x81` → `0x8841C &= ~0x6000` → `0x8C2C0 &= ~4`
   → `0x8C300 &= ~0x10` → `0x8C040 SPEED=1` → `0x8C1C0[19:16]=2` → `0x88610 |= 1`
3. 两端 `LNKCTL2 = 2`（5.0 GT/s）+ 根端口 retrain → 链路训练到 **Gen2 x4**；
4. 确认 Gen2 后写 **宽度声明 x16**：`0x8C040 = (cur & ~0xF8000000) | 0x80000000`
   （安全配方；回退永远整字写 `0x20085800`，禁止用掩码单 bit 清 bit31 —— 实测会掉卡）；
5. **宽度重训**：arm 成功后对两端 retrain 一次，读 `LNKSTA` width；只认 `width=16` 为成功；
   连续 2 次未达 x16 → 判定本机未补电容，本进程内停止重训（重启进程可重试）；
6. **20 ms 看门狗**：只在链路/声明/宽度偏离时补写；掉速后 20 ms 一轮重训，恢复 Gen2 并重新 arm；
7. 如果 live 路径连续失败（很少见），才做 **1 次**整卡复位兜底，复位后仍用 live 写组补一遍。

## 兼容性与安全

- Windows 10 / 11 x64 + **管理员权限**；只认 **P104-100（`10DE:1B87`）**；
- 已验证环境：CPU 直连 PCIe x16 槽（PCH 槽未实测）；
- BYOVD 驱动（WinRing0 / ThrottleStop）可能被杀毒/反作弊拦截，属预期；
- **只写易失寄存器**：不刷 VBIOS、不烧熔丝，断电即恢复；
- 极端情况链路训练失败会把卡从总线打掉：**彻底断电 30 秒**即可恢复；工具会停手并提示，不会反复复位；
- 物理 x16 需要 **AC 耦合电容改造**，不是软件能保证的；工具会把"是否训到 x16"明确打印在日志/状态里。
