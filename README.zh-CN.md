# P104-100：PCIe Gen2 x4 解锁 + 宽度声明 x16（Windows）

**中文** | [English](README.md)

> NVIDIA **P104-100**（GP104 矿卡，`10DE:1B87`）专用的 Windows 工具：
> 把链路从出厂 **Gen1 x4（0.78 GB/s）** 解锁到 **Gen2 x4（实测 1.55 GB/s）**，
> 同时写入 **宽度声明 x16**（`LnkCap maxwidth = 16`），并用常驻看门狗保持。

## 实测结果

| 项目 | 结果 |
|---|---|
| **PCIe Gen2 x4** | ✅ 解锁成功，实测 **0.78 → 1.55 GB/s**（页锁定 H2D / D2H ≈ 1.55 / 1.67） |
| **宽度声明 x16** | ✅ 写入成功（GPU-Z / lspci 显示 `LnkCap maxwidth = 16`） |
| **实际链路宽度** | 仍为 **x4**（物理 lane 只有 4 条）。补上 AC 耦合电容后预计能训练到 x16 —— 我们还没补，待实测后更新 |
| **Gen3 / NVENC / NVDEC** | ❌ 熔丝锁死，见 [`docs/05-功能边界总表.md`](docs/05-功能边界总表.md) |

> 一句话：**带宽翻倍是 Gen2 带来的；x16 目前只是"声明层"，不等同于实际带宽。**

## 工作原理（简述）

1. 通过 BYOVD 驱动（WinRing0 / ThrottleStop）映射 GPU BAR0；
2. 向 BAR0 写"使能位 + 速率请求"（`0x8841C / 0x88610 / 0x8C040` 等），让端点请求 5.0GT/s；
3. **做一次真正的整卡复位（禁用→启用设备）**，让 PCIe 核重新锁存声明为 Gen2；
4. 两端写 `LNKCTL2 = 2` + 触发重训，把链路拉上 Gen2；
5. 常驻看门狗每 20ms 回写一次（NVIDIA 驱动每次 CUDA 初始化都会把 `0x8C040.SPEED` 降回 Gen1）；
6. 链路确认 Gen2 后，再写 `0x8C040 bit31`（**宽度声明 x16**，安全配方：先清 bits27-31 再置 bit31）。

## 关于"要不要整卡复位"（CPU 直连 vs PCH 槽）

- **CPU 直连 x16 槽（本项目的实测环境）**：只写 BAR0 使能位**不会**锁存声明（`LCAP2` 停在 `0x02`），
  必须做一次真正的设备复位才能锁存成 Gen2。实测验证：不复位 100% 失败，复位后 4 秒内锁存。
- **PCH 芯片组槽**：据 Linux 社区反馈（WJNKAC 的 Linux 版分析）以及我们的旧经验，
  可能**只写 BAR0 就能当场锁存**、不需要复位——这类平台可能几秒完成（我们未实测）。
- 本工具**只走复位锁存**这条已验证路径；PCH 上的"无复位"路径没有做，避免不确定性。

## 重要说明

- **x16 是声明层**：GPU-Z 显示 `maxwidth x16` 是真的（寄存器确实变了），
  但实际链路仍是 x4，带宽不变；补完 AC 耦合电容后能否训练到 x16，需实测。
- **GPU-Z 显示 1.1 是正常的**：这张矿卡的 NVIDIA 驱动上报值不可靠；
  以 `status.cmd` 的 RESULT 行 + `bwtest.cmd` 实测带宽为准。
- 驱动是 BYOVD（WinRing0/ThrottleStop），**杀毒软件会报警**，属预期；
  不要和其它 P104 工具同时运行（会互相抢寄存器）。
- 极端情况下链路训练失败会把卡从总线打掉：**完全断电冷启动即可恢复**
  （只写易失寄存器，不损坏硬件）。

## 兼容性

- Windows 10 / 11 x64 + 管理员权限；
- 只认 **P104-100（10DE:1B87）**；不需要 Python（.NET Framework 4.x 系统自带）；
- 已验证环境：**CPU 直连 PCIe x16 槽**；
- x1 矿卡转接板只有 x1 带宽，不在本工具能力范围。
