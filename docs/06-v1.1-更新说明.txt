# 工具 v1.0 → v1.1 更新说明（技术）

> 适用版本：v3.2 发布包 `P104-2.0x16-v1.1.zip`（exe v1.1）
> 本文说明 v1.0 的解锁路径为什么不稳定、v1.1 改了什么、以及实测数据与剩余边界。

---

## 1. v1.0 为什么"时好时坏"

v1.0 的解锁流程是：写使能位与速率请求 → **做一次整卡复位（禁用→启用）** → 等 NVIDIA 驱动重新绑定并把 PCIe 声明锁存为 Gen2 → 两端 TLS + retrain。

这条路径有两个硬伤：

1. **复位锁存的成功率很低。** 对历史日志（`status.txt`，2026-10-29 ~ 10-30）全量统计：
   - 执行整卡复位 **61 次**；
   - 其中"声明锁存超时（20 秒）" **43 次**；
   - 成功锁存 **9 次（14.8%）**；
   - 9 次成功全部发生在复位后第 1 个 4 秒采样；43 次超时之后再等/再重试都没有补上。

2. **冷启动后的第一次运行成功率接近 0。** 初始 `LNKCTL2` 目标速率（TLS）= 0 时，25 次复位样本 **0 次成功**；
   TLS = 1 时约 30%。也就是说"开机后第一次跑"基本必然失败，只能靠后续重试。

这说明问题不在"复位机制"，而在于 v1.0 的写组**没有命中"实时声明"这条路径**，只能靠复位后驱动重新初始化的窗口去碰运气。
（对比实验：项目早期用另一套写组做过"无复位"验证 —— 写完后 `LnkCap2` 在同一秒内 `0x02 → 0x06`，
两端 TLS + retrain 后 `LNKSTA = 0x1042`，并连续保持了 29 分钟。v1.0 的写组没有包含这条路径。）

## 2. v1.1 的解锁路径

### 2.1 主路径：live 写组（不需要复位）

按实测有效的顺序写入（每步都回读校验）：

| 步 | BAR0 偏移 | 运算 | 作用 |
|---|---|---|---|
| 1 | `0x8872C` | `(old & ~0xF) \| 6` | XVE_FUSE_OVERRIDE / LTSSM 覆盖使能 |
| 2 | `0x2241C` | `old \| 0x81` | PTOP_FS4：声明开关位（bit0/bit7） |
| 3 | `0x8841C` | `old & ~0x6000` | PRIV_MISC_1：GEN2_DIS（bits13,14）清 0 |
| 4 | `0x8C2C0` | `old & ~0x4` | CYA_0 bit2 = 0 |
| 5 | `0x8C300` | `old & ~0x10` | CYA_1 bit4 = 0 |
| 6 | `0x8C040` | `(old & ~0xC0000) \| 0x40000` | 速率请求 SPEED = 5.0 GT/s（最高位保留，不带触发位） |
| 7 | `0x8C1C0` | `(old & ~0xF0000) \| 0x20000` | LCTRL2 目标速率 = 5.0 GT/s |
| 8 | `0x88610` | `(old & ~0x1000) \| 0x1` | VSEC 门 |

写完后读 PCIe cap+`0x2C`（`LnkCap2`）：5 GT/s 支持位会在 1 秒内出现（`0x02 → 0x06`），**不需要复位**。
随后两端 `LNKCTL2 = 2` + 根端口 retrain，链路训练到 **Gen2 x4**（`LNKSTA = 0x1042`）。

### 2.2 兜底：整卡复位（很少用）

只有 live 写组连续 3 轮（约 6 秒）都失败时才做复位，并且：

- 复位前显式置 `0x8841C` bit15 = 1 并回读断言（历史 7/7 实测：bit15=0 时复位必然锁不上）；
- 复位预算：**单次运行最多 1 次**、**同一开机周期最多 2 次**、两次间隔 **≥10 分钟**；
- 复位后无论是否已锁存，都用 live 写组再补一遍；
- 设备没有回到总线 → 立即停手并提示 AC 断电，绝不反复重试。

### 2.3 宽度声明 x16

只在 Gen2 已达成且稳定后写：

```
0x8C040 = (cur & ~0xF8000000) | 0x80000000
```

安全规则（实测归纳）：

| `0x8C040` bit31 | bit29 | 结果 |
|---|---|---|
| 1 | 0 | ✅ 安全（声明变 x16，链路不断） |
| 0 | 1 | ✅ 安全（工厂态/回退态） |
| 0 | 0 | ❌ 掉卡（实测 2/2） |
| 1 | 1 | ❌ 掉卡（实测 1/1） |

- 回退**永远整字写** `0x20085800`，禁止用掩码单 bit 清 bit31；
- 宽度已 arm 但链路在 Gen1 时，先整字回退再提速，成功后再重新 arm。

### 2.4 常驻保持

- 看门狗周期 **150 ms**（v1.0 是 20 ms，且每轮都带 CHANGE_SPEED 触发位，等价 50 Hz 触发）；
- 只在四个判据偏离时补写：`LnkCap2`、`LNKSTA` 速率、`0x8C040.SPEED`、`LnkCap.maxwidth`；
- 触发类写（retrain / CHANGE_SPEED）限流 ≥2 秒；
- 连续无法保持时主动退出，交给计划任务重启（不会无限空转）。

### 2.5 工程修复

- **参数白名单**：未知参数 / `-help` 只打印用法并退出（v1.0 会落入默认解锁流程 —— 这是误触发复位的根源）；
- **输出编码**：不再强制 UTF-8，子进程（sc.exe/schtasks）按系统 ANSI 代码页解码；日志不再出现 `�ɹ�`；
- **安装幂等**：已安装状态下重跑 install 不会因驱动 .sys 被占用而中断；
- **卸载**：默认保留驱动策略键（`-purgepolicy` 才清），避免"卸载后再也解不开"；
- **计划任务**：开机 +90 秒 / 登录 +120 秒 / 每 5 分钟自愈（v1.0 是 +60s / +15s / 每 1 分钟 + `-retry 3`，失败时会变成反复复位）；
- **带宽测试**：CUDA 初始化会让链路临时降速，测试结束后会等待保持进程恢复（Gen2 + x16）再退出；状态页在恢复期会给出"正在自动恢复"提示。

## 3. 实测数据（2026-10-30，本机单卡，CPU 直连 x16 槽）

| 场景 | 结果 |
|---|---|
| 出厂态（`LCAP2=0x02`、TLS=0）`-once` | **0 次复位**；写组后 **0 ms** 锁存；3 秒内 Gen2；2 秒后宽度 x16；总 7.4 秒 PASS |
| `-off` 后再 `-once` | **2.8 秒** PASS（retrain 第 1 轮即 Gen2） |
| 一键流程（install + 计划任务）从出厂态 | 40 秒内 `-check` 显示 Gen2 x4 + 声明 x16 |
| CUDA 带宽（页锁定） | **H2D 1.570 / D2H 1.673 GB/s**（Gen1 x4 参考 0.78 / 0.85） |
| 保持 | 状态文件持续刷新；外部干扰（CUDA/带宽测试）后 10–20 秒内自动恢复 |

## 4. 剩余边界

1. **宽度 x16 是声明层**：`LnkCap` 显示 maxwidth=16 是真实写入，但物理只有 4 lane，实际链路仍 x4，带宽不因此提升。补 AC 耦合电容后能否训练到物理 x16，计划 **2026-10-31（周六）实测**。
2. **Gen3（8.0 GT/s）不可解**：熔丝/能力声明无法形成，主机侧无入口。
3. **NVENC/NVDEC/OFA**：OTP 熔丝禁用，不可解。
4. **干净 AC 冷启动后的自动拉起**尚未实测（本次用"计划任务手动触发"覆盖了等价路径）；首次使用建议先手动跑一次一键解锁。
5. 掉卡（设备从 PCIe 总线消失）只能 **AC 断电 30 秒**恢复，软件复位救不回。
