# P104-100：停驱动 + 恢复 BAR0 后写 `0x88140 LINK_WIDTH/COMMIT` 实验（2026-10-31 19:00–19:10）

> 单次实验报告。目标：验证"停 NVIDIA 显示设备 → 恢复 BAR0 访问 → 写宽度配置寄存器
> （`0x88140` LINK_WIDTH[17:12]=16 + COMMIT[0]=1 等 4 个）→ 重新启用/训练 → 读宽度"。
> 这是 §9（停驱动写 `0x8C040`）之后唯一没试过的寄存器组合。

---

## 0. 一句话结论

**`0x88140` 在"停驱动 + BAR0 已恢复"条件下依然读回特权哨兵 `0xBADF5040`、写入被丢弃；
`0x88084`/`0x8C080` 能读真实值但写不进去。链路宽度全程 x4。**
同一会话里 `0x8C040` 写入能回读一致（写通道是活的）⇒ 这不是"驱动在擦"，而是这几个寄存器本身不可从主机侧写。
本次实验不能把宽度做到 x16，与 §10 的最终判定一致，**不改变任何既有结论**。

## 3. 判定

### 3.1 为什么"停驱动 + `0x88140`"也不行

1. **`0x88140` / `0x88460` 是特权门寄存器**：读恒 `0xBADF5040`，与有没有驱动无关；
   旁证：40HX（出厂就是 x16 的卡）读同样两个地址也是 `0xBADF5040` ⇒ 哨兵反映的是**访问权限**，不是宽度。
2. **`0x88084` / `0x8C080` 是只读镜像**：能读出真实值（`0x00453C41` / `0x00000404`），
   但写入被丢弃。`0x8C080` 在 A100 上读 `0x1010`、本卡读 `0x0404`、本卡插 x1 口时读 `0x0101`
   ⇒ 它是**训练结果反射**，不是控制输入。
3. **写通道确实可用**（§2.5 对照：`0x8C040` 写入回读一致），所以"被拒"不是通道问题。
4. **驱动不是擦除者**：设备禁用期间驱动根本没在跑，宽度仍然 x4；启用瞬间也没有 x16 轨迹。

⇒ 结论：这条路线（停驱动 → 恢复 BAR0 → 写 `0x88140` + 3 个镜像 → 重训）**无效**。
宽度 x4 不是"被软件覆盖层压住"，而是 **PHY/strap 只给 4 lane**，寄存器层没有主机可写的入口。

### 3.2 与既有结论的关系

| 既有 | 本次是否推翻 |
|---|---|
| §9（2026-10-31 16:3x）停驱动写 `0x8C040`/`0x8872C` 全失败 | 不推翻，一致 |
| §10（17:0x）物理 x16 不可实现，软件/停驱动/UEFI 无入口 | 不推翻，本次把"`0x88140` 专属路线"这个最后的空白点补上了 |
| `0x8C080` 是训练结果、不是控制 | 不推翻，本次再次实测（写入被丢弃） |

**新增的一条确证**：`0x88140` 的哨兵值与驱动状态无关 —— 之前"驱动/特权门"的归因里，
"驱动"这一半可以彻底排除，剩下的就是寄存器访问权限本身。

### 4.1 `P104Gen2x4Ts` 为什么不能按原样删

实测发现这两个服务不是"实验临时件"的同一性质：

- `P104Gen2x4Wr` / `P104Gen2x4Ts` 是**工具自己**每次 bring-up 时 `sc create/start`、
  holder 退出时 `sc stop/delete` 的（源码 `_gh\v11\src\P104Gen2x4.cs`：
  `SVC_WR="P104Gen2x4Wr"`、`SVC_TS="P104Gen2x4Ts"`、`UnloadServices()`）。
- 实测：`sc stop P104Gen2x4Ts` 时 driver 被 holder 句柄占着 → 卡在 `Stop Pending`，
  而任务自愈会在数秒内拉起新 holder 重新占用它 ⇒ **"删服务"和"保持 Gen2"互斥**。
- 处置结果：holder 停 → 驱动真正卸载 → 用 `sc create ... start= demand` 重建 `P104Gen2x4Ts` 并启动
  → 再 `schtasks /run`。现在两个服务都是**干净的 Running**（无 pending-delete）。
- 副作用：`WinRing0x64` 删掉后，`\\.\WinRing0_1_2_0` 由工具的 `P104Gen2x4Wr` 提供（同一个 `WinRing0x64.sys`），
  **`pci_lib` 依然可用**（已验证：19:09:29 采样 295,758 次正常）。

## 6. 覆盖边界（没做的事）

- **没有**写 `0x8C040`（本实验不需要；只做了一次 arm/还原对照，且都在安全象限）；
- **没有**写 `LNKCTL.bit4`（端点/根端口都没写）、**没有** SBR、**没有** 碰 VBIOS/EEPROM；
- **没有**卸载驱动（只 `pnputil disable/enable`）；
- 每个寄存器**只写一次**，没有反复强写；
- 未在"设备禁用 + D0"下尝试 `0x8B000–0x8B7FF` per-lane PHY 区（上一轮已判定为真实值但无宽度入口）；
- 未做 EFI/引导期写入（用户明确排除该路线）。
