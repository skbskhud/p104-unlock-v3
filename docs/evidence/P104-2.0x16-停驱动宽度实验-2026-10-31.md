# P104-2.0x16 停驱动宽度实验（2026-10-31）

## 0. 一句话结论

**临时禁用 NVIDIA 显示设备（不卸驱动）后写 strap/覆盖 + retrain，物理宽度仍然只有 x4（4/4 步失败）。
驱动不是宽度覆盖层的"擦除者"：禁用→重启用全过程，arm 位（`0x8C040.bit31`）、`0x8872C=6`、
`LNKCAP` 的 x16 声明都没有被驱动改动。物理 x16 的阻碍在 PTAP/PHY/strap（或 PCB lane4–15），
不在驱动层。**

## 1. 目的、授权与安全边界

- 假设：NVIDIA 驱动在链路重训/初始化时把宽度覆盖层擦回默认；禁用显示设备后写 + retrain 可能训到 x16。
- 授权：允许掉卡（AC 断电 30 秒恢复）。目标 = 验证假设，不是必须成功。
- 全程未做：`LNKCTL.bit4`（Link Disable）、SBR、VBIOS/EEPROM 写、竞品 EFI、卸载驱动、改源码/exe、改 relay。
- 本次**没有掉卡**，未触发 AC 断电。

## 3. 实验过程（严格单变量，全程日志）

### 3.1 停保持进程（16:24:55）

- `schtasks /change /tn "P104 PCIe Gen2x4 Bring-up" /disable`（**临时**禁用 5 分钟自愈触发器，防实验中被重拉；
  收尾已恢复 enable）
- `schtasks /end` → `Stop-Process -Name P104Gen2x4 -Force`（硬杀，驱动服务保留）
- 结果：无 P104Gen2x4 进程；`P104Gen2x4Wr` / `P104Gen2x4Ts` 均仍 **RUNNING**（写通道可用）

杀掉 holder 后 25 秒观察（16:25:02–16:25:27）：

- EP LNKSTA `0x1041`（Gen2→**Gen1** x4），`0x8C040=0x80585800` 全程不变（1 段）。
- 即：驱动在无人 hold 时把**速率**降到 Gen1，但**没有动 arm 位**。

### 3.2 禁用显示设备（16:25:34）

```
pnputil /disable-device "PCI\VEN_10DE&DEV_1B87&SUBSYS_123710DE&REV_A1\4&BF82947&0&0008"
→ Device disabled successfully
```
- 设备状态：`Error / CM_PROB_DISABLED`；`nvidia-smi` 如预期失败（驱动不再服务该设备）。
- **未卸载驱动**（`pnputil /disable-device`，不是 `/remove-device` / `pnputil /delete-driver`）。

### 3.3 禁用后 BAR0 不可读（发现，非意外）

| 读项 | 值 | 说明 |
|---|---|---|
| cfg 0x00 | `0x1B8710DE` | 配置空间仍可达 |
| cfg 0x04 | `0x00100400` | Command=`0x0400`，**bit1 MemorySpace=0** |
| PMCSR（PM cap @0x60） | `0x0000000B` | **PowerState=D3hot** |
| BAR0 `0x8C040` / `0x8C080` | `0xFFFFFFFF` / `0xFFFFFFFF` | 内存译码关闭 ⇒ 读回全 F |
| 写通道自检（no-op 写 cfg 0x00） | OK | 配置空间写通道正常 |

**恢复配方（本次新增，两个单字段写，立即生效）**：

1. `cfg 0x04`：Command bit1=1 → `0x0400` → `0x0402`（回读一致）
2. PMCSR `[1:0]`：D3→D0 → `0x0B` → 回读 `0x08`（D0）

之后 BAR0 立即恢复：`0x8C040=0x80585800`、`0x8C080=0x00000404`，
且 `LNKCAP` 仍为 `0x00453D02`（maxwidth 16 声明未丢）。
**该过程不需要 `pnputil /enable-device`、不需要重启。**

### 3.4 写 + retrain（每步：写 → 根端口 LNKCTL bit5（bit4 恒 0）→ 2 秒高频采样 → 失败整字回滚）

| 步 | 写入（原值 → 写入，回读） | 宽度结果 | 处理 |
|---|---|---|---|
| a | `0x8872C` `0x00000006` → `0x00000006`（已是 6，no-op） | EP `0x1041` = Gen1 **x4**，RP `0x7041` x4；191,279 次采样、1 段 | 回滚（无变化） |
| b | `0x8C040` `0x80585800` → `0x80585800`（arm 已置，no-op） | EP x4 / RP x4；193,445 次采样、1 段 | 回滚（无变化） |
| c2 | `0x8C040` `0x80585800` → `0x80585802`（CHANGE_WIDTH，回读自清 `0x80585800`） | EP x4 / RP x4；200,671 次采样、1 段 | 回滚 |
| c3 | `0x8C040` `0x80585800` → `0x80585803`（CHANGE_WIDTH+SPEED，自清） | EP x4 / RP x4；203,592 次采样、1 段 | 回滚（回滚后 195,642 次仍 x4） |

- 每步 `LNKCAP` 都保持 `0x00453D02`（**声明 x16**），`LNKSTA` 宽度恒 4 ⇒ 声明与链路宽度背离。
- 每步 retrain 前后两端 `LNKCTL.bit4` 均 =0（脚本有断言，绝不写 bit4）。
- retrain 后速率停在 Gen1（arm 状态挡住提速，与 v1.1 已知行为一致），宽度测试在 Gen1 下完成；
  宽度与速率无关（声明 x16 时链路仍 x4）。

### 3.5 设备重新启用瞬间（最关键的一次观测）

先启动 45 秒高频采样（后台），再执行：

```
pnputil /enable-device "PCI\VEN_10DE&DEV_1B87&SUBSYS_123710DE&REV_A1\4&BF82947&0&0008"
→ Device enabled successfully（16:27:21）
```

采样结果：**45 秒 / 3,749,691 次读 / 只有 1 段**：

```
t=0.000s EP=0x1041(x4) RP=0x7041(x4) 0x8C040=0x80585800
（直到 45s 结束，无任何变化）
```

⇒ 设备启动 + 驱动重新加载的整个窗口内：**从未出现 x16，链路甚至没有重建**，
arm 位与 `0x8872C=6` 原样保留。启用后 `nvidia-smi` 正常（P104-100 / 8192 MiB / 45°C），
设备 `OK / CM_PROB_NONE`。

### 3.6 对照（证明"不是没法判定"）

holder 关闭、驱动已加载状态下，把 `0x8C040` 整字写回出厂值 `0x20085800`（清 arm，已知安全方向，
bit31 1→0、bit29 0→1）：`LNKCAP` 立即回 `0x00453C42`（maxwidth 4）→ retrain →
297,726 次采样、1 段，EP `0x1041` Gen1 x4。
⇒ 重训后宽度仍 4，且该状态下连 Gen2 都没恢复（受根端口 TLS/驱动策略限制）；
宽度数据与"arm 是否存在"无关，结论不由单次状态决定。

## 4. 结论

1. **驱动不是擦除者。** 禁用显示设备 → 写 → 重启用 → 驱动重新加载，`0x8C040.bit31(arm)`、
   `0x8872C=6`、`LNKCAP` x16 声明**全部原样保留**（45 秒 375 万次采样无一段变化）。
   过去"重训后覆盖层回默认"的现象，来源是硬件侧（链路重训/LTSSM 回到 strap 默认），不是驱动写回。
2. **禁用驱动后写 + retrain 仍 x4（4/4）。** 与驱动在跑时的 13 步单变量（13/13 x4）结论一致：
   覆盖层只改"声明"，到不了 PHY。
3. 因此 **"EFI 在驱动加载前写"这一优势不成立**——驱动既不擦覆盖层，也没有在加载时把链路训成 x16。
4. 物理判断维持不变：**PTAP/PHY 的 lane 配置（strap）只给 4 lane，或 PCB lane4–15 未通**；
   软件（含停驱动）无法突破。
5. 工程副产品：`pnputil /disable-device` 会把端点置 **D3hot + MemorySpace=0**，BAR0 全 `0xFFFFFFFF`；
   用 `Command.bit1=1` + `PMCSR→D0` 两个单字段配置写即可恢复 BAR0 读写。以后任何"停驱动访问 BAR0"
   的实验都可以直接用这个配方。
