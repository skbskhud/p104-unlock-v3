# 物理层实测记录：P104-100 能否训练到 16 lane（2026-10-31）

> 结论先行：截至 2026-10-31，本机这张 P104-100 上我们**尚未实现物理 x16**（暂时没搞定，需要更多时间/其他 P104 样本继续验证）。我们试过的软件侧路径全部失败，
> 链路训练宽度始终为 x4。x4 来自 PHY/strap/板级，不是工具能改变的。
> **部分批次可能不同**；判断依据应为 `LNKSTA` 宽度=16 或带宽 ≈6 GB/s，而不是 GPU-Z 的"链接宽度"显示。

## 1. 实验对象

| 项 | 值 |
|---|---|
| 卡 | NVIDIA P104-100（10DE:1B87），端点 01:00.0，根端口 00:01.0（原生 Gen4 x16） |
| VBIOS | `86.04.7a.00.19` |
| Subsystem | `1237:10DE` |
| 改造 | 补焊 AC 耦合电容（0402 100nF X7R） |
| 上电原始值 | `LNKCAP=0x00453C41`（maxwidth=4）；`LANE_DIS` 熔丝=0 |
| 软件可写后 | `LNKCAP=0x00454D02`（声明 maxwidth=16），但 `LNKSTA` 宽度=4、`0x8C080=0x0404` |

## 2. 我们做过的实验与结果

| # | 路径 | 结果 | 证据 |
|---|---|---|---|
| 1 | 运行时写 `0x8C040` arm（bit31=1）+ `LNKCTL.bit5` retrain | 声明 16 ✅、物理 x4 ❌ | 13 步单变量记录 |
| 2 | 停 NVIDIA 显示设备 + 写 + retrain | 4/4 步 x4；驱动不是擦除者 | `docs/evidence/P104-2.0x16-停驱动宽度实验-2026-10-31.md` |
| 3 | 完整复位（restart-device / disable→enable / remove→scan） | 3 梯度全部 x4；复位确实生效（链路回 Gen1） | `docs/evidence/P104-2.0x16-完整复位宽度实验-2026-10-31.md` |
| 4 | **XVE 位穷举**（117 位、逐位翻转 + retrain、1224 万次采样） | **0 位改变宽度**；`0x8C080` 351 次读恒 `0x0404`；唯一行为位 `0x8C040 bit11`=Gen2 速度位 | `docs/evidence/P104-2.0x16-XVE位穷举-2026-10-31.md` |
| 5 | 停驱动 + 写 `0x88140`（LINK_WIDTH16\|COMMIT）/`0x88084`/`0x8C080`/`0x88460` | `0x88140`/`0x88460` 读回特权哨兵 `0xBADF5040`，写入被硬件丢弃；`0x88084`/`0x8C080` 可读但写被忽略 | `docs/evidence/P104-2.0x16-停驱动写LINK_WIDTH-2026-10-31.md` |
| 6 | 根端口 Link Disable 循环（强制 LTSSM 走 Detect 重新检测 lane） | 根端口 `LNKCTL.bit4` 写入成功、链路断开，**端点 5 秒内未回来 → 掉卡**（只能 AC 断电），不可行 | 实验日志 |
| 7 | VBIOS 只读分析（256KB dump） | DevInit 只写 SPEED/LTSSM/bit11,14,15，**从不写宽度字段 [31:27]、从不 arm、`0x8C080` 全镜像 0 次** ⇒ 启动 x4 不是 VBIOS 设的 | 实验日志 |

## 3. 结论

1. **软件侧没有可用的宽度入口**：可写的声明位（`0x8C040 bit31`）只改 LnkCap，不改变 PHY 训练结果；
2. **硬件特权门**：`0x88140`（LINK_WIDTH+COMMIT）等在驱动禁用后仍返回 `0xBADF5040`，写入被丢弃，属寄存器访问权限；
3. **VBIOS 不写宽度**，改 VBIOS 大概率无效；
4. 因此 **x4 来自 PHY/strap/板级**，本卡无法软件解决。

**补充**：本包已内置「声明 arm + 宽度重训」逻辑。如果某块 P104-100 的**板级（strap/走线/电容）原生支持 16 lane**，本包**可能**通过重训直接解锁物理 x16；但本机这块板尚未实测成功（补电容后仍 x4），需要更多样本验证。

## 4. 关于"部分批次可能不同"

同 VBIOS、同型号 ≠ 同 PCB。若其他批次能到 x16，需对比：
**板子正反面照片 + `nvidia-smi -q` 的 VBIOS/subsystem + 带宽实测数字**。
GPU-Z 的"链接宽度"显示不可靠，真实证据应为 `LNKSTA` 宽度 16 或带宽 ≈6 GB/s。

## 5. 本机最终状态

- **Gen2 x4 + 声明 x16**（`LNKSTA=0x1042`、`LNKCAP=0x00454D02`），`状态.cmd` 显示"已解锁"；
- 带宽 H2D 1.55 / D2H 1.67 GB/s；0 次整卡复位；20ms 看门狗工作正常。

## 7. 我们卡在哪里（欢迎指教）

达到物理 x16 需要同时满足以下条件；标 ❌ 的就是我们目前卡住的地方：

| # | 条件 | 状态 |
|---|---|---|
| 1 | GPU 核心支持 16 lane | ✅ `0x8C004=0x0000FFFF` |
| 2 | **上电时 GPU strap 声明 maxwidth=16** | ❌ **卡点**：上电声明 4 |
| 3 | 插槽/根端口支持 x16、BIOS 不分叉 | ✅（本机确认） |
| 4 | **链路重新走 Detect 时声明仍是 16** | ❌ **卡点**：Retrain 只进 Recovery；LD 循环会掉卡 |
| 5 | 驱动不重置宽度/lane 使能 | ✅（停驱动实测：驱动不是擦除者） |
| 6 | GPU PHY/PTAP 不锁 lane 数 | ❓ 未知（`0x88140` 读 `0xBADF5040`，写不进） |
| 7 | 根端口允许 retrain/复位 | ⚠️ SBR 被 BIOS 锁写；LD 导致端点掉卡 |

**两个真正的卡点**：

1. **上电 strap 声明 = 4**（条件 2）——第一次链路训练必然 x4；
2. **运行时改声明后，链路不会重新走 Detect**（条件 4）——Retrain 只进 Recovery；强行 Link Disable 会掉卡。
