## 五、5 个"隐藏的坑"（代码审查重点）

1. **`PnPReset` 启用阶段用 `list2[0]`**（L601-603）
   单卡时"列表第一个"就是它自己；多卡时如果目标卡在复位期间掉出 present 列表，
   `list2[0]` 可能是**另一张卡** → 会把别人的设备禁用/启用。
   ⇒ v2.0 必须按目标卡的 InstanceId/devInst 定位，禁止取 `[0]`。

2. **`UnlockOnce` 复位后 `FindP104(out _bus,...)`**（L687）
   复位后重新取"第一张卡"。多卡时若目标卡复位后 BDF 变化，会直接操作**另一张卡**，
   把声明写进错误的设备。⇒ v2.0 复位后必须 `ResyncCard(card)` 按 InstanceId/BDF 重定位。

3. **`_bar` 在复位后被重写，但其它卡的 MMIO 映射没重建**（L681-690）
   多卡时若沿用"卸载驱动 + 重装"的自愈路径，**所有**卡的映射句柄都会失效，
   而 v1.6 只重建单卡映射。⇒ 多卡禁止在解锁流程中卸载驱动。

4. **`WriteStatusFile` 直接 `File.WriteAllText`**（L244）
   看门狗/status.cmd 可能在写入瞬间读取 → 读到半截文件。多卡内容更长，窗口更大。
   ⇒ 原子写（临时文件 + Replace）。

5. **`-retry N` 语义**（L1176-1186 + L672）
   v1.6 是"这张卡总共复位 N 次"；多卡如果直接复用全局计数，会变成"所有卡合计 N 次"，
   第二张卡可能一次都轮不到。⇒ 计数放在 `Card.Resets`，每卡独立。
