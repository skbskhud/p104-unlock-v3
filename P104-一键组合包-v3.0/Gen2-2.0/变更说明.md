# P104Gen2x4 **v2.0-beta** 变更说明（多卡 + 可扩展型号版）

> 版本：v2.0-beta（BETA / 实验版）
> 日期：2026-10-23
> 基线：v1.6（单卡 P104-100 稳定版，已实机验证）
> 可执行文件名：**P104Gen2x4.exe**（保持不变，兼容已部署的计划任务与脚本）

---

## 0. 一句话

v1.6 是"一张 P104-100"的工具；v2.0 把它改成"**设备表驱动 + 每卡独立状态**"的多卡工具，
**单卡（VERIFIED）路径保持 v1.6 的操作序列不变**；多卡路径是加法，但**开发者没有多卡环境，
多卡逻辑未经实机验证**——请按 BETA 对待，先 `-list` / `-dry-run` 再真跑。

| 版本 | 定位 | 验证状态 |
|---|---|---|

## 2. 与 v1.6 的差异

### 2.1 功能新增

1. **多卡枚举**：扫描（SetupAPI PnP + PCI 配置空间交叉校验）**所有**受支持型号的卡，
   每张卡有独立的 BDF/BAR0/能力结构/上游端口/计数器。
2. **可扩展设备表**：`Models[]` 集中定义型号（型号名、Device ID、架构、支持级别、说明）。
   以后加型号只改这张表。支持级别：
   - `VERIFIED` = 已实机验证（当前只有 P104-100 10DE:1B87）
   - `EXPERIMENTAL` = 同架构推断 / 未验证（P104-101 1BC7、P106-100 1B83、P106-090 1C07）
3. **`-list`**：列出所有 NVIDIA 卡（不需要管理员、不需要驱动）。
4. **`-dry-run`**：只读预演，显示每张卡"将会执行什么"，**不写寄存器、不复位、不写注册表**。
5. **`-force-experimental`**：允许对 EXPERIMENTAL 型号写入（默认只读检测）。
6. **`-card N`**：只对第 N 张卡执行（配合 `-diag` / `-vbios` / `-dry-run`）。
7. **`-version` / `-help`**：版本与帮助（版本号打印 `v2.0-beta`）。
8. **多卡状态文件**：`C:\ProgramData\P104Gen2x4\当前状态.txt` 改为逐卡段落；
   **原子写**（临时文件 + Replace），避免 status.cmd/看门狗读到半截文件。
9. **热插拔/换槽重枚举**：按住循环每 30 秒重新枚举一次；卡被拔掉 → 移出列表；
   新卡出现（含换槽后 BDF 变化）→ 重新发现并尝试解锁。**不会死等缓存的旧 BDF**。
10. **多卡复位纪律**（硬性）：**一次只复位一张卡**；复位后等该卡声明锁存稳定（最多 20 秒，
    每 4 秒检查 LCAP2）再处理下一张；两次复位起点间隔 ≥3 秒；某张卡失败记录后继续下一张。
11. **按住循环**：逐卡 try/catch，单卡异常不影响其它卡；掉回 Gen1 **只补写声明，不主动复位**；
    单卡时保留 v1.6 的自愈/主动退出逻辑（退出码 8/9 不变）。

### 2.2 单卡路径保持不变（唯一已实机验证的部分）

对"只有一张 P104-100"的场景，v2.0 与 v1.6 的操作序列一致：

| 步骤 | v1.6 | v2.0 |
|---|---|---|
| 等设备/驱动就绪 | 最多 60s，`FindP104` | 最多 60s，`DiscoverSupportedCards`（同一张卡） |
| 写通道自检 | `SelfTestWrite`（写同值 0x1B8710DE） | `SelfTestWrite`（先读再写回同值，等价） |
| BAR0 / 上游端口 / ReMap | 单卡全局 | 同一个 Card 对象，操作序列相同 |
| 驱动策略 | `RMPcieLinkSpeed=1` 等三值 | 同一个注册表键，同样三值 |
| 声明锁存判断 | `LCAP2 & 0x6` | 相同 |
| 整卡复位 | SetupAPI 禁用→启用，等 20s 锁存 | 相同（按卡定位，单卡时即唯一一张） |
| 复位后 | 关驱动→重启服务→重新发现→重映射 | 单卡分支完整保留该流程（多卡分支才不卸载驱动） |
| 6 轮 TLS+重训 | 相同 | 相同 |
| 按住循环 | 20ms 一轮、每 50 采样写状态、慢性失败 1500 轮退出 9、自愈 5 次退出 8 | 单卡时判据与退出码相同 |
| `-once` 返回码 | 成功 0 / 失败 7 | 相同 |
| `-off` 还原常量 | `0xC0B46500` 等 | 相同（仅 VERIFIED 型号；实验卡默认跳过） |

**有意的行为修正（不影响单卡解锁语义）**：

1. **`-status` 的"按住进程"检测**：v1.6 用 `GetProcessesByName("P104Gen2x4")` 时
   **会把执行 -status 的自己算进去**，导致永远显示"运行中"。v2.0 排除当前 PID。
2. **`-status` 的状态文件解析**：v1.6 解析行前缀是 `"当前速率"`，而文件实际写的是
   `"★ 当前链路速率"`，导致实时状态解析实际一直走日志回退。v2.0 同时支持
   `★ 当前链路速率` / `当前链路速率` 和逐卡段落，优先使用实时状态文件。
3. **命名互斥体改为静态持有**：避免 GC 回收 `Mutex` 对象导致命名互斥体提前释放。

| 参数 | v1.6 | v2.0 |
|---|---|---|
| （无） | 单卡 bringup + 常驻 | 多卡逐卡 bringup + 常驻 |
| `-once` | 单卡解锁一次 | **遍历所有受支持卡**，每卡独立 |
| `-retry N` | 单卡最多复位 N 次 | **每张卡**最多复位 N 次（不是总数） |

| `-vbios [-save x.rom]` | 单卡 | 逐卡；多卡时保存文件名自动加 `-BB-DD-F` 后缀 |
| `-off` | 还原单卡 | 逐卡还原（EXPERIMENTAL 默认跳过） |
| `-install` / `-uninstall` | 单型号驱动策略 | 设备表内所有"可写"型号 |
| `-quiet` / `-noreset` | 有 | 语义不变 |
| `-list` | — | **新增**（免管理员/驱动） |
| `-dry-run` | — | **新增**（只读预演） |
| `-force-experimental` | — | **新增**（允许实验型号写入，危险） |
| `-card N` | — | **新增**（只操作第 N 张） |
| `-version` / `-help` | — | **新增** |

### 2.4 返回码

| 码 | 含义 | 变化 |
|---|---|---|
| 0 | 成功 / 已有实例（安全退出） | 不变 |
| 1 | 安装部署失败 | 不变 |
| 2 | -diag 驱动加载失败 | 不变 |
| 3 | -diag 找不到受支持卡 / -vbios 驱动失败 | 不变 |
| 4 | 等待 60s 仍找不到受支持卡 | 不变（文案列型号表） |
| 5 | 配置空间写通道自检失败 | 不变（逐卡判断） |
| 6 | MMIO 映射失败 | 保留（主流程改为逐卡 SKIP，不再整体退出） |
| 7 | -once / -vbios 失败 | 不变（-once：任一可写卡失败返回 7） |
| 8 | 单卡自愈连续 5 次失败，主动退出 | 不变（仅单卡） |
| 9 | 单卡/全部可写卡连续 1500 轮未能保持 Gen2 | 不变（多卡：所有可写卡都慢性失败才退出） |
| **13** | **新增**：多卡模式下连续 3 分钟没有任何受支持卡（全部被拔掉） | 新增，主动退出交给计划任务重新枚举 |

## 3. 多卡设计要点

### 3.1 全局单例 → 每卡对象

v1.6 的 `_bus/_dev/_fun/_bar/_vaLink/_vaPpci/_vaXp3g/_samples/_rewrites` 全部搬进
`Card` 对象；所有寄存器函数、状态函数、状态文件、日志都改成"传入 Card"。
完整清单见附录 A（共 32 处单卡假设）。

### 3.2 卡发现

1. `SetupAPI` 枚举**当前 present 的所有 NVIDIA 设备**（`VEN_10DE`），读取：
   实例 ID、device ID、BDF（`LocationInfo` 解析；回退 `BusNumber+Address`）、
   PCIe 当前/最大速率/宽度（`DEVPKEY_PciDevice_*`）。
2. 设备表匹配：命中的型号才进入操作列表；未命中的只会在 `-list` 显示"未支持"，**绝不写入/复位**。
3. 每张卡用 PCI 配置空间读 `0x00` 交叉校验（PnP 说它是 1B87，配置空间必须也是 1B87），
   不一致 → 跳过并记录。
4. 全部失败时回退到"直接扫 0-255 总线 fn0"（v1.6 的做法）。
5. 枚举结果按 BDF 排序后编号 `#0..#N-1`（稳定编号）。

### 3.3 复位时序（硬性要求，代码保证）

- `UnlockCard(card)` 里才调用 `PnPReset(card)`；`PnPReset` 只操作 `card` 对应的 devInst
  （**按 InstanceId 优先、BDF 次之定位，绝不取列表第一个**）。
- `EnforceResetGap()`：两次复位**起点**间隔 <3 秒时强制等待补足。
- `PnPReset` 内部：禁用 → 等设备离开总线（最多 6s）→ 启用 → 等设备回来（最多 30s，
  期间 BDF 变化会用 PnP 重新定位）→ 等声明锁存（最多 20s，每 4s 检查 LCAP2）。
- 复位完成、锁存判断结束之后，才继续该卡的 TLS/重训；该卡流程结束后才轮到下一张卡。
- 某张卡 `PnPReset` 失败 / 锁存超时：记录日志，**继续下一张**（不中断整个流程）。

### 3.4 按住循环（多卡）

- 每轮遍历所有卡，每卡独立 `try/catch`。
- 只有 `Writable` 的卡写使能/TLS/重训；EXPERIMENTAL 卡只读采样。
- 掉回 Gen1：只补写声明 + 重训，**不主动复位**。
- MMIO 失效：单卡 → 完整 v1.6 自愈（重装驱动、5 次失败退出 8）；
  多卡 → 只对该卡重定位/重映射（节流 1 秒一次，3 次失败移出列表），不卸载全局驱动
  （卸载会毁掉其它卡的映射）。
- 每 30 秒重新枚举：拔掉的卡移出；新卡/换槽后的卡按 BDF 重新发现并尝试解锁。
- 状态文件每 50 轮（≈1 秒，单卡与 v1.6 相同）原子刷新一次。

## 4. 多卡状态文件格式

路径不变：`C:\ProgramData\P104Gen2x4\当前状态.txt`（**原子写**）。
示例（两张卡）：

```
============================================================
P104Gen2x4 v2.0-beta  PCIe 链路状态（由按住进程实时写入）
更新时间 : 2026-10-23 00:19:00
卡总数   : 2
============================================================

=== 卡 #0  01:00.0  P104-100 [VERIFIED] ===
当前链路速率 : Gen2 (5.0GT/s) x4
当前宽度 : x4
声明 : LNKCAP=0x00000001 LCAP2=0x00000006 TLS=2 (含 Gen2)
采样 : 1234 次   补写 : 3 次   复位 : 1 次
状态 : 正常（已解锁并在保持）
判据 : 端点 LNKSTA=0x00000012   上游 00:01.0 LNKSTA=0x00000012
更新 : 00:19:00

=== 卡 #1  02:00.0  P106-100 [EXPERIMENTAL] ===
当前链路速率 : Gen1 (2.5GT/s) x16
当前宽度 : x16
声明 : LNKCAP=0x00000001 LCAP2=0x00000001 TLS=1 (仅 Gen1)
采样 : 1234 次   补写 : 0 次   复位 : 0 次
状态 : 只读检测（EXPERIMENTAL；未写入）
判据 : 端点 LNKSTA=0x00000101   上游 00:02.0 LNKSTA=0x00000101
更新 : 00:19:00

------------------------------------------------------------
【判据说明】当前速率 = LNKSTA[3:0]（1=2.5GT/s 2=5.0GT/s 3=8.0GT/s）；
            端点与上游根端口两端应一致，都是 2 才是真的 Gen2。
【为什么 GPU-Z / nvidia-smi 可能显示 Gen1？】它们读驱动上报值，不是 PCIe 寄存器。
【带宽参考】Gen1 x4 ≈ 0.78 GB/s；Gen2 x4 ≈ 1.55 GB/s（H2D）。
【多卡】状态按卡分段；只有 WRITABLE 的卡会被写入，EXPERIMENTAL 默认只读。
------------------------------------------------------------
结论     : 【正常】2/2 张可写卡已解锁并在保持
按住进程 : 运行中（PID 1234）
============================================================
```

兼容性：
- **单卡时**，文件里额外保留 v1.6 的两行摘要（`★ 当前链路速率` / `当前链路宽度`），
  老用户/老脚本按这两行看仍然成立。
- `-status` 解析器同时支持 **v2.0 逐卡段落** 和 **v1.6 旧单卡格式**（已用构造文件做单元测试）。
- 看门狗/计划任务只依赖"进程存活 + 计划任务触发"，不解析这个文件，不受格式影响。

## 5. 设备表与支持级别

| 型号 | Device ID | 架构 | 级别 | 说明 |
|---|---|---|---|---|
| P104-100 | `10DE:1B87` | GP104 | **VERIFIED** | 主目标；v1.6 单卡路径已实机验证 |
| P104-101 | `10DE:1BC7` | GP104 | EXPERIMENTAL | 同架构推断；默认只读 |
| P106-100 | `10DE:1B83` | GP106 | EXPERIMENTAL | Gen2 寄存器配方未研究；默认只读 |
| P106-090 | `10DE:1C07` | GP106 | EXPERIMENTAL | 默认只读 |

- 设备表在源码 `Models[]` 集中定义；加型号只改这一处。
- EXPERIMENTAL 的"只读"是**强制**的：`-once`/`-bringup`/`-install`/`-off`/按住循环
  都不写其寄存器、不复位、不写驱动策略；只有显式 `-force-experimental` 才放开。
- `-list` / `-status` / `-dry-run`（无驱动路径）仍然会显示它们（只读检测）。
- 其他 `10DE` 设备（包括 HDMI Audio 功能）只在 `-list` 显示"未支持"，工具不会碰。

## 6. ★ 多卡功能的验证状态与风险

### 6.1 已验证（本机，2026-10-23）

> 本机现状：**没有 P104**，只有一张 `10DE:1F0B`（CMP 40HX / TU106，不在设备表 → 未支持）。
> 因此只能做"无卡/只读"验证。

| 项目 | 方法 | 结果 |
|---|---|---|
| 编译 | `csc.exe /target:exe /platform:x64 /optimize+ /codepage:65001` | ✅ 0 错误 0 警告 |
| `-version` / `-help` | 直接运行 | ✅ 打印 v2.0-beta 与完整用法 |
| `-list`（管理员） | 直接运行 | ✅ 正确识别 1F0B 为"未支持"，不加载驱动 |
| `-list`（非管理员） | `runas /trustlevel:0x20000`（受限令牌） | ✅ 无需管理员/驱动即可枚举（PnP 属性路径） |
| `-status`（无状态文件） | 直接运行 | ✅ UNKNOWN + 未在保持 + 任务未注册 |
| `-status`（非管理员） | 受限令牌 | ✅ 任务显示"无法查询"，不误报 |
| `-dry-run`（无受支持卡） | 直接运行 | ✅ 提前退出，**不加载驱动**（零硬件操作） |
| 多卡状态文件解析 | 构造 2 卡状态文件 + 旧 v1.6 单卡格式文件，用环境变量指到临时目录跑 `-status` | ✅ 1/2、逐卡行、OK/READ-ONLY 判定正确；旧格式解析正确 |
| 按住进程自我误判 | 运行 `-status` 观察 | ✅ 已排除自身 PID（v1.6 此 bug 已修） |
| 多卡状态文本生成 | 代码审查（无法造卡） | ⚠️ 未运行；格式已人工核对 |
| 静态检查 | grep 旧全局单例 / 旧函数名 | ✅ `_bar/_vaLink/_vaPpci/_vaXp3g/_rewrites/_samples/FindP104/RemapAll` 均已清除 |

### 6.2 未验证（必须等硬件）

| 项目 | 为什么没验证 | 需要什么 |
|---|---|---|
| **单卡 v2.0 回归** | P104 不在机器上 | 1 张 P104-100（插回后按《测试计划》S1-S8 跑） |
| 多卡逐卡解锁 | 没有第二张受支持卡 | ≥2 张受支持卡（2×P104-100 最好；或 P104-100 + P106-100） |
| 多卡 PnPReset 时序 | 同上 | 同上 |
| 多卡按住循环/热插拔 | 同上 | 同上 + 可拔插环境 |
| EXPERIMENTAL 型号（P106 等） | 无卡、配方未研究 | P106-100 / P104-101 实卡；**默认只读，写需 -force-experimental** |
| GP106 寄存器偏移是否与 GP104 相同 | 未研究 | P106 实卡 + 逐寄存器验证 |

### 6.3 一张卡出错时的预期行为（防御性设计）

| 故障 | 单卡 | 多卡 |
|---|---|---|
| 某张卡 BAR0/能力寄存器读不到 | 主流程返回 6（v1.6 行为） | 该卡标记 SKIP、不写入，其它卡继续 |
| 某张卡整卡复位失败 | `-once` 返回 7 / bringup 继续按住循环 | 记录失败，继续下一张 |
| 某张卡声明锁存超时 | 继续 TLS/重训轮次（v1.6 行为） | 同左，不影响其它卡 |
| 某张卡被拔掉 | 按住循环自愈 5 次后退出 8（交给计划任务） | 移出列表；全部卡没了则 3 分钟后退出 13 |
| 某张卡 MMIO 失效 | 重装驱动重映射（v1.6） | 只重映射该卡，不卸载全局驱动 |
| 某张卡长期保持不了 Gen2 | 1500 轮后退出 9（v1.6） | 只有"所有可写卡都慢性失败"才退出 9 |
| 某张卡是 EXPERIMENTAL | 只读检测、不写入 | 同左（每卡独立） |

### 6.4 风险点

1. **多卡从未实机跑过**：本版本的价值是"设计正确 + 单卡不回归 + 可被后人验证"，
   不是"声称多卡已工作"。多卡用户请先 `-list` / `-dry-run` 并把输出反馈。
2. **整卡复位会黑屏**：与 v1.6 相同，默认每卡只复位 1 次；多卡会**逐张**黑屏，
   不是同时黑。`-retry N` 会放大黑屏次数，谨慎使用。
3. **EXPERIMENTAL 写入危险**：`-force-experimental` 用的是 P104/GP104 的寄存器配方，
   在 GP106 上偏移是否一致**未验证**，可能导致设备异常（通常重启可恢复，但不保证）。
4. **驱动策略是全局注册表**：同一型号的多张卡共用同一个类键，写的是同一个值（符合 NVIDIA 驱动行为）；
   不同型号分别写各自的类键。
5. **BYOVD 风险不变**：仍然临时加载 WinRing0 + ThrottleStop，玩带反作弊的游戏前先卸载。
6. **单卡自愈分支会短时间卸载/重装驱动**：多卡分支**不会**在解锁流程中卸载驱动
   （否则会毁掉其它卡已建立的 MMIO 映射）；多卡重映射只针对单卡。
7. **状态文件依赖按住进程**：不运行时 `-status` 显示的是最后一次写入的内容（v1.6 同样）。
8. **`-vbios` 多卡保存同名文件**：多卡时自动加 `-BB-DD-F` 后缀；单卡保持原文件名。

## 7. ★ 多卡使用须知（BETA）

```
1) 第一次使用先只读探测（不需要管理员）：
      P104Gen2x4.exe -list
   确认每张卡的 #编号 / BDF / 型号 / 支持级别 都对。

2) 再用 dry-run 看计划（会临时加载只读驱动读寄存器，但不写、不复位）：
      P104Gen2x4.exe -dry-run

      P104Gen2x4.exe -once
   或安装常驻（计划任务固定 -quiet -retry 3）：
      install.cmd

4) 复位纪律由代码保证：一次只复位一张卡，等它的声明锁存稳定后再处理下一张，
   两次复位起点间隔 ≥3 秒。按住循环发现掉回 Gen1 只补写声明，不主动复位。

5) 出问题怎么排查：
   · 先跑 status.cmd 看 RESULT / 逐卡行；
   · 需要寄存器级数据：管理员运行 P104Gen2x4.exe -diag；

   · 回退到 v1.6：直接用 v1.6 的 exe 覆盖（计划任务名/参数相同），或先 uninstall 再装 v1.6。

6) 注意：多卡功能未经实机验证。请把 -list / -dry-run / -status 的输出反馈给作者，
   特别是"某张卡在 -dry-run 里识别不对"或"复位后卡没回来"的情况。
```

## 附录 A：单卡假设清单（32 处，摘要）

完整版见 `docs/单卡假设清单.md`。分类摘要：

| 类别 | 处数 | 代表 |
|---|---|---|
| 硬编码单型号 | 8 | `DEVICE_P104`、`FindP104`、`ListPresentP104` 硬编码 `1B87`、`PnPReset` 比较 `0x1B8710DE`、`SelfTestWrite` 硬编码 ID、`FindClassKey("1b87")` |
| 全局单例状态 | 11 | `_bus/_dev/_fun/_bar`、`_vaLink/_vaPpci/_vaXp3g`、`_rewrites/_samples`、`_romPages`、`RemapAll`、`WriteEnables/WriteSpeedGen2/WriteTlsBoth/RetrainBoth/StateLine` |
| PnP 复位单卡假设 | 6 | `list[0]`、启用用 `list2[0]`、只轮询全局 BDF、复位后 `FindP104` 重找、20 秒锁存全局判断 |
| 状态/日志/命令行 | 7 | 单卡状态文件、单卡 RESULT、日志无卡号、参数解析缺 `-list` 等 |

**5 个隐藏的坑**（v1.6 里最容易被忽略的）：

1. `PnPReset` 启用阶段用 `list2[0]` —— 多卡时会去启用**另一张卡**。v2.0 改为按 InstanceId 定位。
2. `UnlockOnce` 复位后用 `FindP104` 取"第一张" —— 多卡且目标 BDF 变化时会操作错卡。
3. 复位自愈路径"卸载驱动 + 重装" —— 多卡会毁掉其它卡映射。v2.0 多卡分支禁止卸载驱动。
4. `File.WriteAllText` 状态文件非原子 —— 多卡内容更长，读到半截概率更大。v2.0 原子写。
5. `-retry N` 全局计数 —— 多卡时会被第一张卡吃光。v2.0 计数在 `Card.Resets`，每卡独立。
