# P104-100 PCIe Gen2 x4 解锁工具 v1.1

本包由 v1.1 源码编译，`P104Gen2x4.exe` 与两个驱动文件的 SHA256 见同目录 `SHA256.txt`。

## 一、这个工具做什么

P104-100（GP104，设备 ID `10DE:1B87`）是无显示输出的挖矿显卡，出厂时 PCIe 链路被限制在 **Gen1 x4**。
本工具通过写入 PCIe 配置空间与 GPU BAR0 寄存器，把链路提升到 **Gen2 x4**，并由常驻进程保持；
同时可以把 PCIe 能力寄存器中的"最大宽度"声明改为 **x16**。

- 工具做的是**易失寄存器写入**：不刷 VBIOS、不烧熔丝、不改 VBIOS。
- 会写入 NVIDIA 驱动的链接策略注册表键（`RMPcieLinkSpeed` / `RmForceEnableGen2` / `RmEnableGen2`），并注册一个 SYSTEM 权限的计划任务。
- **★ 宽度声明 x16 只改"声明层"**：`LnkCap` 的 maxwidth 会显示为 16，但物理链路仍然是 x4。要在物理层跑 x16，需要补 AC 耦合电容/换卡，本包对此不做任何带宽承诺。
- Gen3 不可解（熔丝 `GEN3_DIS` 为 OTP）；编解码器（NVENC/NVDEC）同样被熔丝禁用。两者都不在本工具范围内。

## 二、实测结果（本机，2026-10-30，单张 P104-100）

起点为出厂状态（`LCAP2=0x02`、`TLS=0`，即 Gen1 x4）：

| 项目 | 实测值 |
|---|---|
| `bin\P104Gen2x4.exe -once` | 成功；**0 次整卡复位**，约 **3 秒**完成 |
| LnkCap | `0x00454D02`（maxspeed = Gen2，maxwidth = x16） |
| LnkSta | `0x00001042`（实际链路 **Gen2 x4**） |
| CUDA 带宽 H2D / D2H | **1.570 / 1.673 GB/s**（Gen1 x4 参考 0.78 / 0.85） |
| 计划任务 | 注册为"开机+90 秒 / 登录+120 秒 / 每 5 分钟自愈"；本机手动触发任务后实测 Gen2 x4 保持 |

说明：

- 以上是**本机单卡**实测，本机为 CPU 直连插槽。不同主板/插槽（CPU 直连 vs PCH）时序可能不同，不保证所有平台都是同样的速度。
- **开机自启（AC 冷启动后自动解锁）尚未做完整的干净重启验证**。首次使用建议先手动跑一次"一键解锁"确认可用。
- GPU-Z / nvidia-smi 上可能仍显示 Gen1：它们读的是 NVIDIA 驱动上报值，在这张无显示输出的矿卡上不可靠。以 `状态.cmd` 里的 `LNKSTA` 原始值、以及 `带宽测试.cmd` 的实测为准。

## 三、使用要求

- Windows 10 / 11 x64，**管理员权限**（脚本会自检并提示）。
- 已安装 NVIDIA 驱动（本机 572.75；`带宽测试.cmd` 依赖 CUDA 驱动）。
- 只支持单张 P104-100（本版为单卡设计）。
- `WinRing0x64.sys` / `ThrottleStop.sys` 属于内核态硬件访问组件，可能被杀毒/反作弊软件拦截，必要时先加白名单。

## 四、怎么用（推荐：一键解锁）

1. **完整解压**本压缩包到本地硬盘（不要在压缩包里直接双击运行）。
2. 右键 `一键解锁.cmd` → **以管理员身份运行**。
3. 脚本会依次：安装到 `C:\Program Files\P104Gen2x4` → 注册计划任务 → 立刻启动解锁 → 最多等待 90 秒。
4. 看到 `SUCCESS` 即完成；随后可以跑 `带宽测试.cmd` 验证带宽。
5. 之后正常使用即可：保持进程常驻按住链路；开机 / 登录 / 每 5 分钟的任务会自动兜底拉起。

> 不要同时运行两个实例；安装完不要立刻反复双击（每次都会重启保持进程，可能触发重新训练）。

### 窗口什么时候可以关？（很重要）

| 用法 | 窗口能不能关 | 说明 |
|---|---|---|
| **一键解锁.cmd（推荐）** | **能**：看到 SUCCESS 后可以直接关窗口 | 保持进程在后台 SYSTEM 计划任务里，窗口只是安装器；关机/重启后任务会自动重新解锁 |
| 手动解锁-不装自启.cmd | **不能**：窗口开着才保持 | 这个窗口本身就是保持进程，关窗口 = 停止（链路回 Gen1 x4，属正常现象）。想要"关窗口还能保持"，请改用一键解锁 |
| 状态.cmd / 带宽测试.cmd | 能 | 只读脚本，跑完就能关 |
## 五、验证方法

- `状态.cmd`（只读）：看顶部 `RESULT` 行。
  - `Gen2 x4 ... UNLOCKED` = 成功；`Gen1 x4 ... LOCKED` = 未解锁；`UNKNOWN` = 保持进程未运行或数据过期，等十几秒再跑。
  - 输出里同时给出端点 / 根端口的 `LNKSTA` 原始值，可自行核对。
- `带宽测试.cmd`（只读，CUDA）：看 `H2D`。
  - **H2D ≥ 1.4 GB/s** = Gen2 x4 达标；约 0.78 GB/s = 还停在 Gen1。
  - 保持进程在运行时，测试会先等链路恢复 Gen2 再测（最多测 4 次取最好值）。
  - **带宽测试过程会让链路临时降速约 10–20 秒**（CUDA 初始化导致），属正常现象；测试结束后工具会自动等待恢复（最多 30 秒）并打印"链路已恢复"，`状态.cmd` 在恢复期也会提示"正在自动恢复"。
- 实时状态文件：`C:\ProgramData\P104Gen2x4\当前状态.txt`（保持进程每秒刷新，自带原始寄存器值与时间戳）。
- 运行日志：`C:\ProgramData\P104Gen2x4\status.txt`（解锁过程逐步记录，排障先看它）。

## 六、文件说明

| 文件 | 作用 |
|---|---|
| `一键解锁.cmd` | 安装 + 注册计划任务 + 立即解锁 + 等待结果（需要管理员） |
| `状态.cmd` | 只读查看当前链路与 RESULT（不需要管理员） |
| `带宽测试.cmd` | CUDA 带宽实测（只读） |
| `停止按住.cmd` | 结束任务/保持进程，并把寄存器写回出厂值（不再保持 Gen2，需要管理员） |
| `卸载.cmd` | 停止任务、卸载驱动、可选删除安装目录（需要管理员） |
| `手动解锁-不装自启.cmd` | 前台常驻解锁，不安装计划任务；窗口开着才保持，关窗口即停止（需要管理员） |
| `bin\P104Gen2x4.exe` | 主程序 v1.1（65536 字节） |
| `bin\drivers\WinRing0x64.sys` | 硬件访问驱动（安装时复制到安装目录） |
| `bin\drivers\ThrottleStop.sys` | 硬件访问驱动（安装时复制到安装目录） |
| `SHA256.txt` | 上述 exe 与两个 sys 的 SHA256 |

所有 `.cmd` 均为**纯 ASCII + CRLF**（无 BOM、无 chcp、无中文），这是 v1.0 乱码问题的修复结果。

## 七、高级用法（命令行，可选）

在包目录下执行（或使用完整路径）：

```
bin\P104Gen2x4.exe            解锁并常驻保持（需要管理员）
bin\P104Gen2x4.exe -once      解锁一次，打印结果，不常驻
bin\P104Gen2x4.exe -check     只读查看状态（同 状态.cmd）
bin\P104Gen2x4.exe -bw        CUDA 带宽实测（同 带宽测试.cmd）
bin\P104Gen2x4.exe -off       还原寄存器（需要管理员；先结束保持进程）
bin\P104Gen2x4.exe -install   安装 + 注册计划任务（需要管理员）
bin\P104Gen2x4.exe -uninstall 卸载（保留驱动策略键；加 -purgepolicy 彻底清）
bin\P104Gen2x4.exe -help      帮助
```

选项：`-quiet`（只写日志）、`-noreset`（不做整卡复位）、`-nowidth`（不做宽度声明 x16）、`-retry N`（本次允许的复位次数，1..2，默认 1）。

## 八、与 v1.0 的差异

- **根因修复**：v1.0 把 `0x8841C` 的 `GEN2_DIS` 位写反、并漏写 `0x2241C`，只能靠"整卡复位赌驱动重新初始化"；历史记录 61 次复位仅 9 次成功。
- **live 快路径**：v1.1 先走不依赖复位的实时写组，实测 **0 复位、约 3 秒**完成。
- **复位预算**：默认最多 1 次整卡复位（`-retry` 可到 2），不再"每次触发连做 3 次复位"。
- **150 ms 看门狗**：只在链路偏离 Gen2 时补写，避免持续写寄存器。
- **乱码修复**：所有 `.cmd` 改为纯 ASCII + CRLF，不再混用 `chcp 65001` 与 `sc.exe` 的 GBK 输出。
- **安全修复**：未知参数 / `-help` 只打印帮助并退出，不再落入默认解锁流程（v1.0 曾因乱码导致误触发）。

## 九、限制与边界

- **物理链路仍是 x4**；宽度 x16 只是声明层，不代表带宽提升。物理层能否真正跑 x16 尚待补 AC 耦合电容后实测。
- **Gen3 无解**：端点把目标速率钳回 Gen2，熔丝 `GEN3_DIS=1`（OTP），软件层没有入口。
- 平台差异：CPU 直连插槽本机实测 0 复位；PCH 插槽本机未实测（社区经验是可能只写 BAR0 就能锁存，未经本机验证）。
- 本工具只处理 PCIe 链接层，不涉及算力、编解码、显示输出等其他能力。
- P104 无显示输出，不要期待它变成显示卡。

## 十、故障恢复

- **掉卡**（设备管理器里消失 / `nvidia-smi` 报 `GPU is lost` / PCI 配置空间读全 `FF`）：
  关机，**拔掉电源线等 30 秒（AC 断电）**再开机。不要反复软复位/热重启。
- **一键解锁 FAILED**：① 再跑一次；② 跑 `状态.cmd` 看 RESULT；③ 冷启动后再试。
- **想临时回到出厂状态**：`停止按住.cmd`；彻底移除：`卸载.cmd`。
- 宽度 x16 声明是易失的，重启后回到出厂的声明值（x4）。

## 十一、安全声明

- 本包 exe 由 v1.1 源码编译，SHA256 见 `SHA256.txt`；请勿使用来源不明的同名 exe。
- 工具会写入 NVIDIA 驱动策略注册表键，并注册一个 SYSTEM 权限的计划任务；`卸载.cmd` 会删除该任务并卸载驱动，但**按设计保留**驱动策略键（需要彻底清除时加 `-purgepolicy`）。
- 所有寄存器写入均为易失操作，重启即恢复；不做 VBIOS / 熔丝级持久化修改。
